# Design language · Creative Engineering

This is the small, intentional visual system shared by the [GitHub profile](https://github.com/zuhayer03) and this repository. Its purpose is to help visitors understand the work, not to compete with the work.

## Principles

1. **Show substance first.** Lead with identity, current focus, inspectable projects and clear links. Keep decorative experiments optional.
2. **Editorial, not cyberpunk.** Calm typography, paper-like surfaces, dark slate, soft sage and lavender. Avoid neon frames, excessive gradients, and large icon collections without context.
3. **One visual language.** Original pastel project illustrations, white-backed tool logos, restrained borders and consistent two-column galleries.
4. **Purposeful motion.** Animate the network ring, chart bars, orbit and small glints. Keep headings, body text and clickable targets steady. Favor 2–3 second loops.
5. **Respect accessibility.** Every animated GIF includes a reduced-motion SVG fallback; image descriptions explain content. Strong contrast, readable sizes, and explicit link destinations.
6. **Tell the truth.** A demo is a demo. A prototype is a prototype. Never confuse decorative contribution graphics, fictional datasets, or teaching code with production experience.

Original project cards intentionally retain their own distinct colors: mint (Network Monitor), lavender (Finance Tracker), apricot (AlgoArena), and sage (ThreatTrace).

## Information architecture

The profile follows: **Who I am → Current focus → Four real builds → Explore → Tools → Optional playful visuals → Contact**.

This repository follows: **Overview → Projects → Browser experiments → Folder map → Run instructions**. Each project folder preserves its own source and test instructions.

## Animation source of truth

The original vector illustrations live in `zuhayer03/zuhayer03/assets/`. The published GIFs and PNG fallbacks are generated by `scripts/render_existing_artwork.py` in that repo and automatically published to its `output` branch via GitHub Actions.

The source SVGs are kept intact. There should be no hand-edited GIFs that diverge from their source art. The contributions snake and Pac-Man use real GitHub contribution data, and the separate playable maze game is a browser demo.

## Future changes checklist

- Can the visitor find a project's **code and tests** in one click?
- Does the page remain readable without animation?
- Does motion communicate anything, or is it merely distracting?
- Are original art, text and colors consistent across the profile, archive, and project pages?
- Are all projects described at their real implementation stage?
- Do the automated checks pass after publishing?

Less decoration. More clarity. Keep the playful details where they earn their space.
